# Generator

`mlocgen` ([`tools/mlocgen/`](../../tools/mlocgen)) writes everything in `src/generated/` from the pinned upstream sources. It is a C program built with the library and links it, so it parses locale ids with the library's own parser and writes the layout the library reads ([data.md](data.md)). [Updating data](../operations/updating-data.md) gives the commands.

## Inputs

- **CLDR's XML release** (`tools/cldr-release.txt`): `common/main`, `common/supplemental`, `common/bcp47`, `common/rbnf`, `common/collation`, `common/subdivisions`, `common/uca/FractionalUCA.txt`, and the DTDs.
- **The IANA tzdb source** (`tools/tzdb-release.txt`), never zic's output or the system's zones.
- **Maul Unicode,** linked, for General_Category (currency spacing), case mappings (titlecasing tables) and NFD (collation).

ICU's data and CLDR's JSON are not inputs. ICU4X reads CLDR's JSON for most data and takes collation from ICU's exported tables; the JSON has no collation, and reading the XML gives one upstream for everything, with the collation builder ours to prove.

## Resolving CLDR

CLDR's inheritance is resolved as CLDR's own tools resolve it (`XMLSource.ResolvingSource`, which writes CLDR's JSON): a value is looked up along the locale's parent chain per component (explicit parents, else truncation, else root, a non-likely script going straight to root in the main component), skipping the inheritance marker `↑↑↑` and values below the draft threshold (contributed, as ICU takes); when no locale has it, root's alias for the path, then the path without its `alt`, then with `count="other"`, are looked up again from the locale asked for. [`tools/mlocgen/cldr.h`](../../tools/mlocgen/cldr.h) holds the details. The DTDs give the attribute defaults and which attributes distinguish paths.

CI compares the generator's resolution of every path of every locale with CLDR's JSON of the same release (`tools/check_resolution.py`). They agree on all but a handful, each listed with its reason in `tools/resolution-exceptions.txt`; the check fails on any other difference and on a listed one that no longer differs.

## Compilers in the generator

Work that ICU does at run time each time a formatter is made is done here once, so the library only selects:

- **Plural rules** become C functions, one per distinct rule set, in `src/generated/plural_rules.c`.
- **Date patterns:** each locale, calendar and semantic field set gets its pattern by ICU's `DateTimePatternGenerator` matching, run in the generator (`skeleton.c`, `semantic.c`); interval patterns likewise (`interval_gen.c`). The library never parses a pattern or a skeleton at run time.
- **Number patterns** are compiled into affixes, digit counts and group sizes.
- **Spell-out rules** are parsed as ICU4C reads them and stored compiled; written back as ICU's `getRules` writes them, every group is byte for byte ICU4C's.
- **Collation:** the root from `FractionalUCA.txt`, every tailoring's rules through a builder that follows ICU4C's `CollationBuilder`, the fast Latin tables and the alphabetic index labels ([collation.md](collation.md)).
- **Time zones:** the tzdb source compiled as zic compiles it ([dates-and-zones.md](dates-and-zones.md#time-zones)).
- **Chinese and Dangi year tables** from an astronomical model in integer arithmetic.

Where ICU4C's data build and CLDR's inheritance give different answers, the generator follows CLDR, and the difference is listed with the oracle check that found it (`tools/skeleton-exceptions.txt`, `tools/interval-exceptions.txt`).

## Output

The output depends only on the inputs: the generator walks files and keys in a fixed order and writes the same bytes on every run and platform. CI regenerates `src/generated/` from the pinned sources and fails on any difference, so a hand edit or a stale file cannot pass. The code tables' hash, which enters the data version, is computed from the generated code.

The grammar lexicons are generated by Python scripts instead (`tools/gen_turkish_marks.py`, `gen_finnish_types.py`, `gen_hanja_finals.py`) from their pinned external sources; `tools/gen_pow5_tables.py` writes the shortest-digits tables. Each has a `--check` mode that CI runs.

## Other commands

`mlocgen` also answers the oracle checks: `resolve` (a path's resolved value), `chains` (CLDR's parents of a locale), `plural-samples`, `skeletons`, `intervals`, `semantic` and `zones` (compiled offsets for zic comparison). They exist for `tools/check_*.py` and the cldr CI job; `zonesfile` is the one command a program's build may use.
