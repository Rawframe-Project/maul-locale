# Checks

What verifies a change, locally and in CI, and the time each may take.

## Locally

`tools/check.sh` runs the checks in three tiers; each includes the one before it. Its builds are the CI cells' presets from `CMakePresets.json`.

| Tier | Runs | Budget |
|---|---|---|
| `changed` | The source, module, length, API documentation and snippet rules, the organization's documentation check, `clang-format` on the changed C files, and the `linux-clang-20-asan` preset (assertions on) with the CTest labels the changed files reach. | under 2 minutes on a built tree |
| `pr` | Every rule on every file, the tables generated from data in the repository, clang-tidy, the `linux-gcc-14` and `linux-clang-20-asan` presets, and 10 seconds of fuzzing per target. | under 10 minutes |
| `full` | Also the shared library with the package test and Clang Release, 60 seconds per fuzz target, `src/generated/` regenerated from the pinned CLDR and tzdb, every check against those releases (`tools/check_cldr.sh`), and the Hanja finals against Unihan. The releases are fetched into `out/cache` once. | under 20 minutes |

Run `changed` before every push. On the shared development machine, run `pr` and `full` through the workspace's heavy-job wrapper. Builds go to `out/<preset>` and the other trees to `out/check-*`, each with its log beside it.

## In CI

`.github/workflows/ci.yml` runs on every pull request, on every push to `main` and every night. The Linux jobs run in the organization's CI image, pinned by digest, and install nothing. The ruleset requires only its `required` job, which passes when every other job passed or was skipped, and the title check.

| Job | What it guards |
|---|---|
| `changes` | Whether a pull request changes anything beyond documentation; when it does not, the jobs that build are skipped. |
| `docs` | The organization's documentation check: allowed files, the em dash, record numbers, page sizes, links. `tools/external/` is excluded. |
| `zizmor` | The workflows: injection, persisted credentials, permissions, unpinned actions. |
| `checks` | `clang-format`, the family's source rules, the module graph, lengths, API documentation, documentation snippets, that the documentation site builds, the shortest-digits tables and the Turkish and Finnish lexicons against their generators, and clang-tidy; the clang-format and clang-tidy steps fail when they find no file, so a check never passes on nothing. It runs on documentation changes too. |
| `build` | One call of the organization's `cpp.yml` per preset: GCC 14 and Clang 20 in Release, GCC 14 on 64-bit Arm (the same image, on GitHub's Arm runner), Clang with AddressSanitizer and UBSan (each test repeated up to three times on a pull request, so a flaky one fails before it merges), the shared library with the package test, macOS and `clang-cl` on Windows. All build with warnings as errors. ccache is restored on every run and saved only from `main`. |
| `msvc-headers` | Every public header compiled by MSVC's `cl` as C17 and C++17 with `/W4 /WX`. |
| `generated` | `src/generated/` regenerated byte for byte from the pinned CLDR and tzdb. |
| `cldr` | `tools/check_cldr.sh`, beside `generated`: the generator's resolution against CLDR's JSON, CLDR's conformance files, collation against CLDR's and ICU4C's tables, the zones against `zic`, `zdump` and `zoneinfo`, the date tables of ICU4C in `test/`, and ICU's matcher test ([conformance.md](../internals/conformance.md)). Both jobs restore the releases cached by their pins; `main` saves them. |
| `unihan` | The Hanja finals against the pinned Unihan database, an 8 MB download: on every run of `main` (each push, the night, a manual run), and on a pull request only when it changes the pin, `tools/gen_hanja_finals.py` or the generated header. |
| `fuzz` | Every fuzz target from its seeds in `test/seeds/`, four at a time: 20 seconds each on a pull request, 60 seconds on `main` and at night. It fails when no target was built. A finding uploads the logs and the crashing input. |
| `web` | The `web` preset: the library and its tests under Emscripten, run by CTest through Node, with the same skipped-test check and failure logs as the other cells, and the size of the static library. The image has no Emscripten, so this job uses the runner and the emsdk action. |

`pr-title.yml` checks that the pull request title is a conventional commit with a scope from `AGENTS.md`, and `pr-gate.yml` closes a pull request from outside the organization unless it closes an issue labeled `accepted`. `codeql.yml` runs CodeQL on every pull request and on `main`, building with GCC 14 (an advanced setup, since the default one builds with the runner's GCC 13). `scorecard.yml` grades the repository's security practices weekly for the README badge, and Dependabot proposes updates of the pinned actions once a week in one pull request.

## Tests

Each suite in `test/` is one executable, registered with CTest under its name and labeled with it; `tools/check.sh changed` picks suites by these labels. The white-box suites (`WHITEBOX` in `CMakeLists.txt`) include `src/` for a data layout or validator no public call reaches, and are not built in shared builds. No test reports itself skipped; a test preset that finds no test fails, and so does a CI cell where a test is skipped or not run.

The `conform_*` programs are not tests: they read files outside the repository (CLDR's test data, the tzdb), so the `conformance` target builds them and `tools/check_cldr.sh` runs them.

## Assertions

`MLOC_ASSERT` (`src/invariant.h`) states an internal invariant: a precondition between the library's own modules or a state that cannot occur unless the library is wrong. It traps in every build without `NDEBUG`, which includes the Debug, sanitizer and fuzz builds, and compiles out of Release builds. Input from callers and data files is never asserted: it is validated and refused with a status in every build.

## Budgets

Over a budget, tests are pruned or merged before anything else is added. The pull request check takes about the time of its slowest job, `generated` or `cldr`, five to seven minutes each; the build cells take two to three minutes each, less with a warm ccache.
